## 1. 使用环境与目标

我使用多个 Agent 和套餐：Codex 主要经 CC Switch 切换路由；MiniMax 直连套餐；ZCode 直连 BigModel／Z.ai；火山使用 Token／Agent Plan，具体类型待核实；公司内部模型平台仅在公司网络或 VPN 下可访问。

目标是在 Mac 本地运行后台服务，通过 localhost 网页统一查看套餐、费用、到期日、额度、恢复时间、历史趋势，以及能够取得的模型成功率和速度。第一版为个人单用户工具。

现有调用路径全部保留。套餐查询独立运行，不要求模型请求经过本系统。后台程序能否访问公司接口需独立验证，不能把浏览器可访问等同于程序具备网络、SSO 和证书条件。

## 4. 数据模型与口径

以下为逻辑模型，映射到已有结构，避免重复建表。

| 对象 | 作用 |
| --- | --- |
| Provider | MiniMax、BigModel、火山、公司平台等供应商 |
| Account | 账号别名、区域、凭据引用 |
| Subscription | 套餐名、价格、币种、付费周期、到期日 |
| QuotaBucket | 独立共享额度池，如五小时、周、月、模型专属池 |
| QuotaSnapshot | 某时刻的额度状态与来源 |
| UsageRecord | 供应商明细或本地日志中的消耗记录 |
| HealthAggregate | 渠道、模型、时间窗口和观测范围下的健康统计 |

要求：

- 一个供应商支持多个账号，一个账号支持多个套餐或额度池。
- 多模型或多个 Agent 共用一个额度池时，不能复制后重复汇总。
- Agent 与供应商分开：ZCode 是工具；Codex 经第三方路由产生的消耗不能归为 OpenAI 官方订阅消耗。
- 凭据只以引用关联，不返回给普通前端查询接口。
- 金额保留币种；年付／季付折算月均成本与当月实际支出分开。
- UTC 存储，默认 Asia/Shanghai 展示；供应商重置规则保留原时区。

额度池字段至少包含：名称、单位、总量／已用／剩余／百分比（均可为空）、窗口类型、重置时间、来源、采集时间、最后成功时间和状态。

采集状态与额度状态分开：采集失败不代表额度耗尽，未知不代表零。保留最后成功快照，同时标记过期；展示已用百分比时明确方向。

只有快照时展示“额度使用趋势”。不可简单累加快照、通过滚动窗口余额差推导精确消耗，或将周期重置、退款、升级、额度回补当作新增消耗。

## 5. 采集与供应商适配

优先复用已有适配器。每个适配器声明是否支持套餐信息、当前额度、历史用量、模型明细、平台健康统计；不支持的能力明确返回状态。

| 优先级 | 对象 | 核验与实现 |
| --- | --- | --- |
| P0 | MiniMax | 国内／国际区域、具体套餐版本、额度百分比方向 |
| P0 | BigModel／Z.ai | ZCode 实际使用的账号、区域和编程套餐 |
| P0 | Codex 官方订阅 | 使用已有查询方式，不声称覆盖全部 ChatGPT 功能限制 |
| P1 | 火山 Token／Agent Plan | 确认具体套餐；普通推理用量不等于套餐余额 |
| P1 | 公司平台 | 已核实的额度、健康接口和鉴权 |
| P2 | 其他供应商 | 手工套餐登记和后续适配入口 |

公司平台接入要求：支持明确的 Base URL、鉴权和必要自定义 CA。缺资料时请求脱敏 curl 与 JSON 示例，明确要哪一个接口和字段。用户提供的内部域名仅在本地使用。模型推理 Key 不自动等同于余额查询权限。

轮询应支持超时、退避、抖动、单账号并发保护、手动刷新节流。尊重 Retry-After；401/403 转为凭据异常而不是持续重试或轮换凭据绕过限制。不同供应商故障互不阻塞。优先复用上游调度器。

网络失败、VPN 断开、电脑休眠导致采集中断时，显示数据缺口。只有供应商有历史接口时才尝试补回，不虚构缺失样本。

## 6. 页面要求

沿用上游设计体系，中文界面，桌面优先；项目名称为“模数 · Modial”，浏览器标题、导航品牌与新增文档统一采用该名称。支持现有主题，不先进行大规模视觉重写。若用户提供参考截图，将其用于健康页信息布局，不复制内部品牌或账号信息。

### 6.1 总览

已登记套餐数、按币种分组的月均订阅成本、额度不足、即将到期、采集异常、最后成功更新时间。注意月均订阅成本与实际支付金额不混算。

### 6.2 套餐页

按供应商／账号分组卡片：套餐名、账号别名、区域、价格、付费周期、到期日、各额度池进度条和恢复时间、来源与新鲜度。提供手动刷新、编辑、暂停采集、官方控制台入口。

价格和到期日允许手工填写，标记来源；自动采集不覆盖用户维护字段。无接口的套餐仍可登记，并明确“仅手工管理”。

### 6.3 用量页

支持时间、供应商、账号、套餐、模型筛选。不同单位分别绘图，实际支付／套餐抵扣／API 等价估算分开。只有存在日志来源时开放 Agent／项目维度，否则说明未接入。

### 6.4 健康页

每行以“供应商＋渠道＋模型”标识，展示近十分钟、一小时、二十四小时成功率及样本数、首字延迟、输出速度、最后观测时间。

明确区分“平台整体”“我的调用”“主动探测”，禁止混合聚合或默认直接排名。仅有二十四小时汇总时，不推算更短窗口。优先读取公司平台已有统计。

第一版不强制引入 LiteLLM、Prometheus、Grafana 或代理。没有调用数据的供应商显示“未接入调用监控”；健康页允许部分覆盖。

## 7. 健康统计口径

- 仅 HTTP 200 不足以判定流式调用成功，须观察正常结束或上游明确结果。
- 上游尝试成功率与最终请求成功率分开，保留重试归属。
- 单列额度不足、限流、鉴权、网络错误、上游错误和用户取消。
- 明确成功率分母，用户取消单列且不默默计为上游故障。
- 首字延迟以首个有效生成内容为准，不将 SSE 心跳、角色字段当作内容。
- 输出速度需有有效 token 计数及对应生成时长；缺数据不计算。对外部汇总数据保留其原始计算口径。
- 样本不足显示提示；零样本显示“—”，不显示 100%。
- 非流式总耗时不冒充首字延迟。可显示 p50／p95，但仅在数据足够且可计算时展示。
- 不同采集来源需去重；调用日志和额度快照是两种视角，不能相加。

## 8. 本地部署与安全

默认绑定 127.0.0.1，复用并检查认证；不暴露公网。优先现有可靠凭据机制，文件存储则限制权限、加入 gitignore。不虚称全部数据已加密。

日志脱敏 API Key、Authorization、Cookie；普通 API 返回不含密钥。后台可配置代理和 CA，但不得擅自改系统代理。复用上游能力时审查自动请求、自动额度启动、外部通知等行为，默认禁用不必要的外发。

提供无真实凭据的配置模板、启动／停止／状态／日志命令。手工运行稳定后提供可选 launchd 配置，不直接替用户安装系统服务。提供数据库迁移前备份、恢复与升级说明。

## 10. 必要验证

重点测试真实风险，不写仅复述实现的测试：百分比方向、多账号隔离、共享池去重、额度重置与升级、未知总量和缺字段、401/403/429/超时、VPN 中断、过期数据、币种与时区、流式中断、重试、小样本、请求去重、日志脱敏和迁移兼容。

1. 真实账号已验证（记录验证日期和套餐类型，不记录密钥）。
2. 样例测试通过，待真实账号验证。
